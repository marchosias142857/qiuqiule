# v6.5.2 · 方形 Boss、独立子弹时间与彗星拖尾

本次落实四项修订：Boss 场地恢复正方形；瞄准子弹时间按操作机制独立实现；赌徒五选一采用上三下二布局，所有可撞击奖励球增加清脆音效与击碎反馈；玩家和分身增加仅在高速时出现的半透明彗星拖尾。仅更新现有 Site。

## 子弹时间流畅度修复（2026-11-03）

用户反馈子弹时间明显卡顿。定位为主循环先缩小累积时间，再等够 1/120 世界秒才更新位置：0.3 倍速因此仅有约 36 次位置更新／秒，60Hz 屏幕约 40% 的帧重复原位置。修复后以 120Hz 真实时间调度，只将每次模拟推进量乘以慢放倍率；0.3 倍速每步推进 0.0025 世界秒。玩家、敌球与分身共用该更新节奏，正常速度仍使用原有步长。

时间片仍记录原有倍率，保留松手、取消和阶段切换时的时间守恒。局部碰撞停顿仍按真实时间消耗，原有 0.3／0.6 倍率、1.2／0.9 秒窗口与 0.5 秒恢复段不变。拖尾历史按世界时间留点，实时端点逐步跟随球体，避免更密的慢放更新挤掉尾部；转向保留拐点，停止运动时不续命。

修复验证包含 30／60／120Hz 下玩家、敌球和分身每帧移动、实际绘制位置前进，0.3／0.6／1 倍世界时间与真实停顿时长核对，以及慢放与正常时间片混合、清场、Boss 胜利和奖励流程回归。拖尾比较三档速度倍率下相同路径的完整长度和逐步跟随，并检查冻结、反向及内存上限。预览服务仍返回 `relay unavailable`，未验证浏览器实屏或手机真机帧率。本次不增加渲染插值，不承诺消除超过 120Hz 或不稳定帧率下的全部顿挫。

修复后全套 627／627 项测试通过，0 失败、0 跳过，用时 18.096 秒；其中真实入口 169 项，拖尾 12 项。脚本语法与差异检查通过，离线缓存标识更新为 `v6.5.2-smooth-aim-2`。日志为 `v652-smooth-aim-tests.log`，测试中的 DOM、Phaser 和音频边界使用替身，不等同于设备帧率实测。

## Boss 场地

Boss 入场仍先完成标准清场，之后只挑战带恶魔角的旧膨胀球。场地收拢为居中正方形，墙面按方框法线反弹；绘制与碰撞共用正方形外接边界，常规小圆角仅用于视觉，最大为 22px，物理圆角半径为 0。四角可活动，不保留不可见的圆形约束。窗口尺寸变化与阶段过渡继续约束球体位置。

v6.5.1 的专用低阻力 0.04/s、Boss 与墙面法向反弹保速 98.5%、有限补能、眩晕后继续撞击收尾、胜后双次奖励均保留。Boss 最大半径继续保守地取 `min(0.75 × 场地半边长, 场地半边长 − 玩家直径 − 0.1u)`；初始半径为 `min(4.8u, 0.82 × 最大半径)`，最小半径为 `min(2u, 0.45 × 最大半径)`。方场四角提供额外可活动空间。Boss 末杀边框震动仍仅移动视觉轮廓，碰撞位置不变。本局击败 Boss 后结算戴王冠，分身复用主球外观而无眼睛的修复继续保留。

## 独立瞄准子弹时间

| 项目 | v6.5.2 规则 |
| --- | --- |
| 范围 | 无尽普通战斗与 Boss 战，保持随时接手；闯关与奖励选择继续原操作。 |
| 激活 | 按住达到 120 ms 或移动达到 6 px。更短、更小的轻点不发射、不慢放。 |
| 时间倍率 | 正常 0.3 倍；系统减少动态效果时为 0.6 倍。反馈强度设为 0%、60% 或 100% 均不改变这两档倍率。 |
| 默认窗口 | 从手势激活起最多维持 1.2 秒，再用 0.5 秒线性恢复至 1 倍。移动手指不重置窗口，松手立即恢复。 |
| 实时部分 | 手指轮廓、瞄准提示、HUD 与局部碰撞停顿继续使用真实时间。模拟按 1/120 真实秒调度，每步世界时间乘以当前倍率。 |
| 中断 | 暂停、取消、失焦、切后台、重开、尺寸变化与阶段结束清理手势并恢复时间；迟到的松手不能发射。 |

分析文档第 7.1 节明确要求减少动态效果时仍保留 0.6 倍瞄准慢放，第 12.6 节则有笼统的“不慢放”约束。本次按照用户明确要求，将第 7.1 节作为独立操作机制的规则；清场、胜利和结尾等表现性慢放以及其他动态反馈仍遵守各自的减少动态效果限制。

本地统计只记录成功发射的有效瞄准。每条时长为“激活到松手的真实秒数”与“本局最低倍率窗口加 0.5 秒恢复段”中的较小值；快速有效甩射可以记为 0 秒，轻点、无发射长按、取消、暂停、试玩和闯关不作为样本。记录容量最多为最近 60 次。至少取得 20 个样本且中位时长严格大于 0.9 秒后，从下一局将最低倍率窗口缩短为 0.9 秒，恢复段仍为 0.5 秒；否则下一局使用 1.2 秒，后续较短瞄准也可使窗口恢复至 1.2 秒。当前局窗口在开局时锁定，不会在 Boss 战或一次拖拽中途变化。

统计仅写入本机 `qiuqiule-aim`，存储失败时继续使用内存记录。JSON 导出包含累计完成次数、最近样本、样本中位数、校准阈值、下一局与当前局窗口，供人工验收使用；不上传统计。

这里的样本容量与最少样本数是本项目为避免少量操作改变规则所选的实现值；文档规定的是 0.9 秒中位数阈值与缩短方向，并未指定这两个采样参数。

## 奖励球布局与击碎反馈

赌徒触发的五选一中，三颗奖励球位于玩家上方，两颗位于下方，玩家位于两排之间；赌徒的长按小图示也使用同样排列。布局按 `1.28 × 奖励球半径` 预留外环空间，并为完整名称保留 31px；短屏先缩小间隙，再缩小奖励球。试玩显式划定的可用区域不会扩展到控制面板后方。选择期间屏幕尺寸变化后重新排列并将玩家归中、停球，避免旧运动直接造成误选；仍通过弹射撞击完成选择。该布局规则只改变五选一。

击中奖励球的反馈覆盖所有可撞击的奖励选择，包括普通三选一、起步强化、Boss 两轮奖励和试玩。命中位置、方向与入射速度交给普通敌球共用的碎片机制，使用被选球的颜色；声音在同一帧播放短促、明亮的奖励叮声。一个实际选择只产生一次音效与碎片，不借此增加敌球击杀数、连击或分数。闯关现有自动强化没有可撞击的奖励球，不新增选择流程。

## 半透明彗星拖尾

拖尾仅作用于战斗中的玩家球和分身，颜色跟随玩家主题，绘制于球体下方。高速时渐入，随着物理速度提高进一步延长；横向采用两侧较深、中央较浅的同色透明渐变，不使用硬描边或背景色遮挡。轨迹连续平滑，最尾端保留非零宽度并平直截断，呈现彗星尖端被截掉的开口感，不收尖，也不加圆帽。每条横向色带沿路径保持连续透明度，停止生成后整体随时间淡出，避免纵向分段接缝。球体轮廓和眼睛仍是视觉主体。普通敌球不增加拖尾，避免满场运动痕迹遮挡目标。

轨迹取球体最近的实际位置，撞墙与转向后沿路径折返，不直接沿速度反向拉一条可能穿墙的长三角形。历史容量、寿命与最大长度均有上限；传送、窗口尺寸变化、暂停、重开及阶段切换清空历史，避免跨屏或跨场景连线。拖尾纯视觉，不改变物理、碰撞或照片。减少动态效果与零反馈强度下关闭拖尾，瞄准子弹时间仍独立生效。

| 参数 | 实现值 |
| --- | --- |
| 显隐阈值 | 速度达到 20u/s 时启用，降至 18u/s 时退出，避免在一个阈值附近闪烁。 |
| 长度 | 令 `w` 为 18–40u/s 之间的 smoothstep 速度权重，长度为 `r + (min(7r, 8u) − r) × w`；20u/s 是启动滞回阈值。从球后缘逐步增长，22u/s 已有短尾，40u/s 达到全长；满速可见尾长约不超过三个球直径。 |
| 宽度 | 头部半宽为球半径的 68%；尾端保留头部宽度的 20%，横向平直截断，不画端盖。 |
| 透明度 | 峰值为 `0.24 × 反馈强度 × √w`。横向九条相邻同色带的权重对称为 `8%、40%、100%、36%、6%、36%、100%、40%、8%`，两侧较深、中轴较浅，外缘羽化；同一色带沿路径不再分段改变透明度。 |
| 历史与采样 | 最长保存 0.22 个世界秒，每球最多 48 个点；历史约每 1/120 世界秒留点，最新端点每个物理步跟随，转向时保留拐点，不依赖绘制帧率。 |
| 平滑 | 一轮 Chaikin 平滑，曲线留在采样点凸包内；配合有界尾宽，避免平滑过程把路径推到方墙外。 |
| 绘制上限 | 每个横向色带为沿整条路径的一个连续多边形，共 9 次填充／球；各色带相邻而不重叠，不使用白色或背景色覆盖。 |

这些具体参数是本项目的实现调试值，不是文献给出的最优值。长度使用物理速度，历史随世界时间老化，子弹时间中仍保持相应速度的长度与慢放路径。

## 参考依据与取舍

分析文档第 14 页原本建议默认不使用拖尾，以保护动作冲击与极简观感。本次用户明确提出新增拖尾，并最终指定流畅柔顺、尾部平直截断的开口效果，因此采用仅高速出现的短、淡、平滑轨迹；不加入全屏光效、强发光或长时间残留。

- [LearnOpenGL：Breakout Particles](https://learnopengl.com/In-Practice/2D-Game/Particles) 的打砖块示例让粒子跟随球、随寿命淡出并复用容量。借鉴短寿命与复用思路，不照搬发光粒子外观。
- [Unity：Trail Renderer](https://docs.unity.com/en-us/engine/6000.0/manual/visual-effects/lines-trails-billboards/rendering-trails/class-trail-renderer) 说明沿程宽度曲线、颜色渐变、点寿命、最小采样距离与角点处理，用于平滑渐隐轨迹的技术设计。
- [BallEngine：Ball Trails](https://ballengine.app/help/visual-customization/ball-trails) 区分短尾运动模糊与长路径记录，并说明距离采样和长尾、发光的渲染成本。采用短尾、有限采样、无额外发光。

这些来源提供表现与实现参考，不证明本游戏某个阈值、长度或透明度最优。

## 手动验收

1. 进入 Boss 试玩，确认先清场后收拢为正方形，斜向撞墙与四角反弹正确；改变窗口尺寸后无圆弧空气墙，继续检查连续多弹与末杀反馈。
2. 在无尽普通战斗和 Boss 战拖拽，依次设置反馈强度 0%、60%、100%，确认均为同样的瞄准慢放；持续按住超过两秒后恢复正常，松手、暂停和切后台不残留慢放。
3. 开启系统减少动态效果并重载，确认瞄准仍以 0.6 倍推进，拖尾及不必要的动态表现关闭。
4. 试玩五选一，确认玩家上三下二，分别从两侧发射可选择对应奖励；检查横竖屏以及长按名称示意。普通三选一、起步强化与 Boss 各轮奖励都应有一次清脆声和一次定向碎片。
5. 以轻拉与满拉比较拖尾：低速不出现，高速增长；撞墙后路径折返，球体保持清楚。暂停、重开、结算和旋转屏幕后不保留旧尾迹；圆球、多边形、照片与分身表现一致。
6. 导出本地瞄准统计，核对样本数与中位数；试玩和被取消的手势不增加样本。达到校准条件后的当前局时限不变，下一局才使用较短窗口。
