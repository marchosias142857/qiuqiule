# v10.0.5 BGM 启动与切换修复

## 问题与修复

排查复现了三处可造成延迟的控制流：首曲等待独立 OfflineAudioContext 全量解码；Boss 激活先等待普通曲；预备 Boss 依赖播放 Context 已解锁。它们会叠加本地 MP3 读取与解码时间，短 Boss 战可能在曲目就绪前结束。

现在以正式播放 Context 统一解码，并共享两首曲目的压缩字节下载；Context 暂停或 resume 尚未完成时也能准备当前曲目，但不提前发声。Boss 独立等待自身资源，普通曲在后台准备，迟到时静音接入且始终只保留一个常驻声源。恢复播放的微任务竞态也已修复，普通曲不会出现未跟踪的重复声源。

从开局和每个常规阶段提前准备下一场 Boss。静音、隐藏、重开、快速进出 Boss 时保留或取消正确的准备意图；过期解码不会错误播放或占用 Boss PCM。失败下载可重试，20 秒下载期限避免一次卡住的请求永久阻断后续尝试。解码复制原始字节，避免 decodeAudioData 转移输入导致下一轮失效。

安卓 Capacitor 7.4.3 原本已设置 mediaPlaybackRequiresUserGesture=false，没有重复修改壳层策略。APK 直接读取内置资源，跳过网页专用 Service Worker 的重复预缓存；旧注册仅在相同应用作用域退役，不强制刷新或触碰存档，现有受控页面在下一次启动脱离旧 Worker。网页/PWA 仍保留离线缓存。

原有曲目、循环点、Boss 音量修正和 650ms 交叉淡化保留。v10.0.4 的母球及战斗平衡逻辑未改动。
