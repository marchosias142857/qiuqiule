# v6.0.1 · 任务 1：基础打击反馈验收

本次范围是已确认计划中的任务 1，交付到现有 Site 供试玩验收。计分公式、阶段目标、刷新节奏、强化效果、Boss 胜负规则和闯关玩法保持原有规则；暂不实施任务 2 及之后的内容。本次不更新 GitHub 仓库或 Android APK。

## 已实现的反馈

| 项目 | 当前表现 |
| --- | --- |
| 局部命中停顿 | 普通轻击继续运动；伤害达到最大 HP 的 30% 时产生短停顿。击杀、Boss 命中和进入眩晕采用不同强度。只冻结相关球体，其余球和世界计时继续，一发累计新增冻结时间不超过 250 ms。 |
| 击杀与碎片 | 被击杀目标短暂停留后，从接触点沿冲击方向碎裂。碎片继承碰前速度，同一发连续击杀增强碎片反馈；不改变击杀得分。 |
| 分级音效 | 普通命中、击杀、Boss 命中分开处理；击杀采用瞬态、主体和低频分层，同一发连续击杀逐级升高音阶。一次致命命中不会再叠加普通命中音。 |
| 飞行形变 | 战斗中高速飞行沿速度方向拉长，减速后自然收回；保持面积，圆球、多边形皮肤和照片外观使用一致的变形。 |
| 分数反馈 | 加分后数字弹动约 160 ms，滚动最多 250 ms。连续加分从当前显示值衔接到新的总分，重开立即归零。 |
| 蓄力反馈 | 每次拖拽首次跨越 50%、80%、100% 拉距时分别触发一次轻触震动，边框保持固定。弹性拉扯声随拉距和拉动变化，手指停住后自然消退。回拉再越线不重复震动；松手、取消或中断时平滑停止拖拽音。 |
| 边框与微缩放 | 撞墙位置附近的边框短暂增强，约 120 ms 收回。击杀时以接触点为中心微缩放，约 80 ms 到峰值、200 ms 回原位；最后一杀进入奖励转场时也完整播放，暂停、重开及其他阶段切换时复位。 |
| 保留的视觉约束 | Boss 命中不出现白光覆盖；暂停按钮保持透明背景；保留现有标题与全局字体。 |

## 强度与减少动态效果

- 设置中新增“反馈强度”，范围 0%–100%，默认 60%，修改后保存在本机。
- 60% 是本次默认体验。100% 可以用于辨认反馈细节，不代表推荐强度。
- 0% 用于对照：关闭新增停顿、微缩放、飞行拉伸、边框增强及分数动画，并停止蓄力音；仍保留基础碎片和必要的事件音效。静音继续由原有声音设置控制。
- 系统启用“减少动态效果”后，重新载入页面：单次停顿最多 50 ms，不推镜、不抖动、不慢放；分数直接更新，边框不加粗，碎片运动减弱。
- 新安装默认开启拖拽表情；已保存的开启或关闭选择继续保留。

## 六个直接验收场景

在 Site 地址后追加 `?feedback-demo=1` 打开验收入口；已有查询参数时追加 `&feedback-demo=1`。普通链接不会显示这组额外控件。

点击场景按钮后会自动发射一次，也可以继续手动拖拽弹射。每次再次点击同一按钮都会重置该场景。

| 按钮 | 操作与预期 |
| --- | --- |
| 轻击 | 观察自动命中：目标受伤但存活，不触发命中冻结。 |
| 重击 | 观察自动命中：目标受伤但存活，相关球体短暂停顿。旁边独立运动的球继续移动，用来检查停顿是否局部生效。 |
| 击杀 | 观察目标短暂停留、随后从接触点碎裂；听击杀音，查看分数滚动和微缩放。 |
| 连续击杀 | 等待约 3 秒，不需额外输入即可看到至少两次击杀；比较后续击杀的音阶和碎片变化。 |
| 末球奖励 | 自动完成达到阶段目标的最后一杀，确认停顿、碎片、击杀音和微缩放正常出现，然后进入奖励选择；奖励提示音稍后响起。 |
| Boss | 观察自动命中后 Boss 缩小和分级音效；Boss 身上不应出现白光。此验收场景暂时停止 Boss 膨胀，方便继续试打。 |

验收场景使用真实碰撞与绘制流程，临时目标布局仅用于检查任务 1。场景中的得分不写入最高纪录，也不修改关卡或皮肤进度；反馈强度设置仍会保存。点击“返回游戏”回到正常主页，或正常重开后，即退出验收状态，普通游戏成绩恢复保存。

## 建议逐项验收

1. **比较强度。** 在验收页先用 60% 试玩六个场景，再切到 0% 重复“击杀”和“重击”，确认差别容易辨认；最后恢复到你觉得舒服的强度。
2. **检查局部停顿。** 反复进入“重击”场景，看被撞双方短暂停顿时，旁边的独立球是否仍在移动。不要把整个场地都停下来的效果判为通过。
3. **检查连续反馈。** 进入“连续击杀”，确认连续碰撞有不同音阶，碎片不会遮住后续路线，分数最终准确稳定，场景不会卡住。
4. **检查蓄力。** 回到正常游戏，在可以拖拽时逐渐拉到半程、约八成、满拉，再回拉并重新拉满。拖拽全程不应推动边框；停住手指时拉扯音应自然消退。同一次拖拽不应反复震动；松手或取消拖拽后不应残留蓄力音。下一次拖拽应重新允许三级反馈。
5. **检查暂停与重开。** 击杀后立即暂停，再继续；再次暂停并重开。画面不应停留在放大状态，不应留下死亡目标残影，旧分数不应重新出现，暂停按钮不应变绿。
6. **检查外观。** 分别使用圆球、已解锁多边形和自定义照片试玩，确认飞行拉伸与碰撞形变一致，没有照片与轮廓分离、眼睛瞬移或边缘裁切。
7. **检查设置保存。** 把强度调到 30%，重新载入，确认仍是 30%；再恢复 60%。已有关闭拖拽表情的设置应继续保持关闭。
8. **检查减少动态效果。** 在系统中开启该选项并重新载入，重复击杀和撞墙，确认没有推镜与抖动，分数直接更新；关闭该选项后也需重新载入恢复普通表现。
9. **检查成绩隔离。** 记下普通游戏最高纪录，在验收页制造击杀并进入结算，然后返回游戏；原纪录不应被试玩成绩覆盖。正常游戏破纪录后仍应能够保存。

## 已执行验证与待验收项

自动化场景测试运行真实入口模块与场景逻辑，并替换 DOM、音频设备和 Phaser 边界；覆盖六种场景各运行 3 秒、数据有限性、轻重击区分、连续击杀、音效事件、分数与镜头时序、残影清理和纪录隔离。本次补充回归验证拖拽边框保持不动、达到阶段目标的末球反馈和奖励转场。全套 301 项测试与语法检查通过；其中真实入口场景 70 项、音频 17 项。

手机实际震动能否触发、震动强弱、扬声器上的音色层次，以及连续试玩的舒适度，仍需要真机主观验收。浏览器和设备可能不支持震动，不能仅凭没有振动判定三级阈值逻辑失效。上述自动化结果不等同于真实 GPU 浏览器画面或手机帧率验证。
